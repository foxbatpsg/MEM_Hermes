# Начало нового проекта

## Что сделать вам

1. Скопируйте эту папку в место нового проекта. Если там уже есть файлы с такими именами, не перезаписывайте их — попросите агента объединить правила.
2. Откройте `docs/wishes.md` и напишите обычным текстом, что вы хотите получить. Можно начать с нескольких предложений. Специальное оформление не нужно.
3. Дайте агенту задание:

   > Прочитай AGENTS.md, INDEX.md и docs/wishes.md. Помоги уточнить пожелания и предложи структуру ТЗ. Создавай документы по мере согласования со мной. Индекс, коды требований и конфигурацию поддерживай сам.

**Список документов заранее не нужен. Демонстрационных требований нет, заменять ничего не требуется.** На старте нормативный корпус и реестр пусты.

## Что такое ID

ID — постоянный уникальный код записи, а не имя файла. Например, `R-001` обозначает конкретное требование, `Q-001` — вопрос или принятое решение, `G-001` — критерий приёмки. Это только объяснение обозначений, не заведённые требования проекта.

Коды назначает агент, когда появляются реальные записи. Благодаря им ссылки не теряются при перестановке разделов. Самостоятельно нумеровать пожелания вам не нужно.

## Минимальный комплект

- `docs/wishes.md` — место для ваших пожеланий, пока без содержимого проекта.
- `AGENTS.md` — инструкция агенту: как из пожеланий готовить ТЗ и поддерживать порядок.
- `INDEX.md` — пустая карта будущих документов и реестр требований.
- `governance.json` — настройки валидатора; агент пополняет список файлов по мере появления ТЗ.
- `scripts/validate_index.py` — проверка связности реестра и нормативных определений, ссылок `INDEX.md` и актуальности генерируемых реестров.
- `scripts/build_refs_registry.py`, `scripts/query_refs.py` — реестр ссылок корпуса (`REFS-REGISTRY.md/.json`) и точечные запросы к нему; область индексации берётся из `governance.json`.
- `scripts/build_cards_registry.py`, `scripts/query_registry.py` — слой карточек задач; включается файлом `cards.json`, когда карточки появятся.
- `scripts/test_validate_index.py`, `scripts/test_refs_registry.py`, `scripts/test_cards_registry.py` — тесты инструментов, не требования проекта.
- `README.md` — эта инструкция.

Отдельные скилл, журналы, шаблоны и CI на старте не нужны: процедура уже в AGENTS.md, решения можно записывать в индекс. При росте проекта агент может предложить дополнительные файлы.

## Проверка — для агента

Нужен Python 3.9+ без внешних библиотек. Из корня нового проекта:

```shell
python -B scripts/validate_index.py --strict
python -B scripts/build_refs_registry.py --check
python -B -m unittest discover -s scripts -p "test_*.py" -v
```

Windows: можно использовать `py -3`; Linux/macOS: `python3`. По умолчанию корень вычисляется относительно расположения скрипта, либо задаётся абсолютным путём через `--root`.

Код 0 — PASS, 1 — нарушение, 2 — ошибка конфигурации. Пустой старт должен давать `records=0, errors=0, warnings=0`. Это означает лишь корректность стартовой структуры, а не готовность ТЗ.

Когда появятся утверждённые документы, агент внесёт относительные пути с `/` в `corpus`, определения с постоянными ID и якорями — в документы, строки с адресами — в реестр. Пожелания остаются свободным исходным текстом вне нормативного корпуса. Обязательные согласованные ID вносятся в `required_ids`.

Валидатор выявляет пропущенные/дублированные записи, отсутствующие определения и файлы, неверные адреса Canonical и статусы. Он не проверяет смысл требований, соответствие всем пожеланиям, все ссылки Markdown и полноту настроенного списка документов. Проверка не запускается сама и не блокирует Git; её запускает агент. Автоматическую проверку можно добавить позже.
