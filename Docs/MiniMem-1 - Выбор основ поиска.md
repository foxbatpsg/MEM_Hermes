# MiniMem-1 — выбор способа построения основ поиска

Конспект для агентов. Вопрос уже исследован, повторно не открывать без
новых данных. Запись в реестре доработок — RB-11; измерительный скрипт —
`minimem/tools/compare_stemming.py`.

## Вопрос

Заменять ли собственный усечитель слов на морфологический движок
(Snowball, pymorphy) ради качества поиска на русском.

## Ответ

**Нет. Не менять.** Среди готовых морфологических движков вариантов нет:
Snowball измерен и на ключевых словах хуже текущего решения.

## Что измерено

Скрипт сравнивает, сходятся ли формы одного слова между собой, то есть
найдёт ли запрос «памяти» запись со словом «память». Запуск интерпретатором
venv Hermes, где `snowballstemmer 3.1.1` установлен.

| Группа форм | наш усечитель | Snowball |
|---|---|---|
| память / памяти / памятю | сходится | **расходится** |
| журнал / журнале / журналы | сходится | **расходится** |
| записка / записки / записками | сходится | сходится |
| поиск / поиска / поиском | сходится | сходится |
| бэкап / бэкапа / бэкапу | сходится | сходится |
| восстановление / восстановить | расходится | расходится |
| накопление / накопить | расходится | расходится |

Расхождение Snowball на двух главных словах:

```
память -> памя     (Snowball)   |  памят   (наш)
памяти -> памят    (Snowball)   |  памят   (наш)
журнал -> журна    (Snowball)   |  журнал  (наш)
```

Причина: русский портер агрессивен, срезает мягкий знак и приставки. Свой
усечитель режет по явно перечисленным хвостам (51 окончание в
`mm/query.py`) и на этих словах сходится.

Там, где расходятся оба, причина не в алгоритмах, а в разных лексических
основах: «восстановление» и «восстановить» не сведёт ни стеммер, ни усечение.

## Почему не поставить и Snowball

1. **Измерено хуже** на ключевых словах — замена ухудшит совпадение форм.
2. **Не переживёт обновление Hermes.** venv управляется `uv`
   (`uv = 0.12.15` в `pyvenv.cfg`) и пересобирается при обновлении, поэтому
   ручная установка пакета пропадёт. Это риск, а не запрет: пакетов в venv 285,
   `pip` рабочий, но окружением владеет не MiniMem.

## Что делать

**Точечно дописывать окончания в `mm/query.py` по материалу RB-05.** Порядок:
смотрите реальные запросы через `minimem search "..." --explain`, находите
слова, которые не сошлись, добавляете нужный хвост в `STEM_ENDINGS`.

Дёшево, обратимо, улучшает ровно то, что мешает, и не создаёт зависимости.

## Граница вывода

Вывод «не менять» следует из измеренного на 2026-09-26. Он пересматривается
при одном условии: **появится материал RB-05**, показывающий, что промахи
идут не от несходимости окончаний, а от несводимости лексических основ
(«восстановление» / «восстановить»). Тогда усечение принципиально не справится
и придётся выбирать между своим стеммером на стандартной библиотеке и
внешним процессом со своим окружением. Оба варианта отложены осознанно: первый
требует словаря русского языка в коде, второй — нового компонента с точкой
отказа, и до данных они преждевременны.

## Не делать

- Не «улучшать» `query.py` заменой на Snowball без нового замера.
- Не добавлять зависимости в venv Hermes.
- Не считать расхождение форм дефектом системы: критерий качества — находит ли
  поиск нужную запись, а не совпадают ли основы у всех слов.
