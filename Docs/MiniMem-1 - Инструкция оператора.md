## 2. Все команды

Рабочий каталог для команд: `C:\Projects\MEM_Hermes\minimem`.

| Команда | Что делает | Когда использовать |
|---|---|---|
| `python -B minimem.py status` | Путь журнала, число файлов, состояние SQLite, режимы, конфигурация | «Работает ли вообще» |
| `python -B minimem.py verify` | Целостность: журнал против индекса, дубликаты, повреждения, курсоры, дайджесты | Подозрение на расхождение |
| `python -B minimem.py stats` | Агрегаты за день: захват, поиск, задержки, уплотнение | Раз в неделю, основная сводка |
| `python -B minimem.py search "текст" --explain` | Поиск без вставки, с оценками и причинами отсева | Проверить качество выдачи, калибровка |
| `python -B minimem.py doctor --backup-settings D:\minimem-backup\backup.json` | Таймауты Hermes и MiniMem, суббюджеты, копия | Регулярно; после смены таймаутов |
| `python -B minimem.py rebuild-index` | Пересоздать SQLite из журнала | После удаления `minimem.db` |
| `python -B minimem.py rebuild-digest --all` | Пересоздать все дайджесты | Если дайджесты повреждены |
| `python -B minimem.py compact` | Снять старые записи с поиска | Вручную; уважает `compaction_rule2_enabled` |
| `python -B minimem.py show <event_id>` | Исходная запись из журнала | Проверить, что записалось на самом деле |
| `python -B minimem.py re-project` | Перепривязать записи к проектам | После смены `project_mapping`; делает копию журнала |

**Коды возврата у всех команд:** `0` — успех, `1` — нарушения, `2` — ошибка
конфигурации. В PowerShell: `echo $LASTEXITCODE`.

**`verify` без `--projects` — обычно достаточно.** Флаг `--projects` нужен,
только если менялся `project_mapping`.

## 3. Регламент

| Когда | Что делать | Повод беспокоиться |
|---|---|---|
| Ежедневно | Ничего. Бэкап идёт сам в 23:00 | — |
| Еженедельно | `stats` | ненулевой `turns_skipped` (потерян ход), `таймаутов` > 0, `body withheld` > 0 |
| Еженедельно | `doctor --backup-settings …` | не «без проблем» |
| Ежемесячно | Тренировка восстановления в пустой каталог | — |
| После обновления Hermes | `hermes hooks doctor` | обновление могло снять регистрацию хуков |
| При жалобах «память не работает» | `status`, затем `verify`, затем `search --explain` | — |


## 4. Симптомы и действия

### В новой сессии не вставилась выжимка прошлой работы

1. `status` — режимы включены? `mode_return` должен быть `вкл`.
2. `search "..." --explain` — поиск находит записи? Если да, дело не в памяти,
   а в выборе дайджеста.
3. Лог:

   ```shell
   Select-String -Path C:\Projects_loc\LLM_Wiki\memory\logs\minimem.log -Pattern 'return_|catch_up|digest_' | Select-Object -Last 15
   ```

4. `rebuild-digest --all`, затем повторить ход. Если после пересборки выжимка
   появилась — был повреждён файл дайджеста.

### В ходе диалога память не возвращается

Смотрите, был ли ход. Поиск не запускается на первом ходе сессии и на ходе,
где уже вставилась выжимка, — это по норме (§12 п. 2), а не поломка.

### Журнал не растёт

1. `status` — `mode_capture: вкл`?
2. `hermes hooks list` — все три хука присутствуют?
3. `hermes hooks doctor` — «All shell hooks look healthy»?

**Важно:** при запуске Hermes не в терминале неразрешённый хук пропускается
**молча**, без ошибки на экране. Если скрипт переехал или переименован, память
перестанет писаться, и ничто об этом не сообщит. Проверьте, что команда в
`%LOCALAPPDATA%\hermes\shell-hooks-allowlist.json` совпадает с текущим путём
к скрипту. Устранение этого риска — доработка RB-15, решение не принято.

### `verify` пишет «проблемы»

Возьмите первую строку с `проблема:` и пришлите её. Типовые случаи:

| Сообщение | Значение | Действие |
|---|---|---|
| `записи журнала, отсутствующие в индексе` | индекс отстал | `rebuild-index` |
| `недействительные journal_cursors: файл уменьшился` | журнал правили извне | `rebuild-index` |
| `внешне переписанные файлы журнала` | файл правили извне после индексации | `rebuild-index`, затем разобраться, кто правил |
| `повреждённые записи журнала` | битая запись в разборе | такая запись не индексируется; остальные работают |
| `записи формата новее поддерживаемого` | запись новее MiniMem | предупреждение, не поломка; обновить MiniMem |

- **Запускать `rebuild-index` часто.** Операция безопасна, но лишний раз

1. Скопировать каталог кода MiniMem и журнал.

### `stats` показывает `turns_skipped` больше нуля

**Это единственное значение, за которым стоит потеря данных.** Ненулевое
означает, что рабочий ход Hermes передал, а MiniMem не смог записать. Найти
причину:

```shell
Select-String -Path C:\Projects_loc\LLM_Wiki\memory\logs\minimem.log -Pattern 'journal_append_failed|journal_lock_timeout'
```

Обычная причина — занятый диск или другая программа держит файл журнала.
Рассосётся само, когда причина пройдёт, но потерянный ход не вернётся.

**Оговорка про старые числа.** Правка счётчиков введена 2026-09-26 (RB-16).
До неё пустые служебные события попадали в `turns_skipped`, а настоящие
отказы записи в него не попадали вовсе. Поэтому в записях лога за 2026-09-25
и 2026-09-26 стоят значения, записанные по старым правилам: `turns_skipped: 3`
при `пустых событий: 0`. Новый подсчёт действует только для записей,
сделанных после правки. Лог не переписывается — он источник истины.

Отличить старые значения от новых можно по наличию поля `empty_events` в
записи лога либо по операции `journal_append_failed` / `journal_lock_timeout`:
если ни одной такой записи в логе нет, то ненулевой `turns_skipped` —
остаток старых записей, а не свежая потеря.
