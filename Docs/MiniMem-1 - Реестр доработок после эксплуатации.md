# MiniMem-1 — Реестр доработок после эксплуатации

Назначение:
фиксировать решения, которые нельзя принимать без реальной эксплуатации MiniMem-1.

Статусы:

- Кандидат — идея зафиксирована, данных пока нет
- Собраны данные — есть статистика/журнал/калибровка
- Готово к включению — можно менять ТЗ/код
- Отклонено — решение принято не делать
- Перенесено в v2 — выходит за рамки MiniMem-1

## Начальные записии

| ID | Тема | Что нужно решить после эксплуатации | Критерии | Статус |
|---|---|---|---|---|
| RB-01 | Включать ли правило 2 уплотнения | Сейчас compaction_rule2_enabled=false. Нужно решить, можно ли включать правило 2 без вреда для памяти | Нужны реальные данные: доля записей с usage_count=0, которые позже оказались бы полезны; качество поиска; возраст записей; эффект после rebuild-index | Кандидат |
| RB-02 | Переход catch-up с варианта A на B или adaptive | Сейчас catch-up повторяется максимум 2 хода в сессии. Нужно решить, не слишком ли это мягко для длинных сессий | Статистика pending_catch_up, таймауты, частота незавершённых предыдущих сессий, длина сессий, нагрузка на pre_llm_call | Кандидат |
| RB-03 | P1-тесты v1.6 | Часть новых проверок не делаем обязательной сразу, чтобы не затягивать приёмку | После стабилизации кода можно перевести часть P1 в обязательные | Кандидат |
| RB-04 | Расширение redaction | Встроенный набор шаблонов v1.6 минимальный. Потом можно расширять под реальные секреты в Hermes-логе | Частота ложных срабатываний/пропусков, типы токенов, производительность regex | Кандидат |
| RB-05 | Калибровка поиска | После накопления журнала нужно формально замерить precision/recall, долю пустых выдач, шумность OR-запросов | Реальный корпус реплик, ожидаемые релевантные/нерелевантные записии | Кандидат |
| RB-06 | Манифест дайджестов | Если выбор последнего дайджеста по полю Создан окажется неудобным, можно добавить производный манифест в SQLite | Частота fallback на mtime, коллизии, повреждённые заголовки | Кандидат |
| RB-07 | Альтернативный механизм блокировки журнала | Если msvcrt.locking окажется проблемным на Windows, рассмотреть advisory lock file | Параллельные post_llm_call, stale lock, поведение при kill процесса | Кандидат |
| RB-08 | CLI override для правила 2 | Возможно, понадобится minimem compact --enable-rule2 для административного запуска без правки config | Удобство эксплуатации, риск случайного включения | Кандидат |
| RB-09 | Наблюдаемость поверх логов | Потом можно сделать сводку: почему память не вернулась, сколько таймаутов, сколько duplicate, сколько damaged records | Реальные инциденты и частота диагностики | Кандидат |
| RB-10 | Автоматический maintenance курсоров | Если индексатор будет часто отставать, рассмотреть фоновую или периодическую догоняющую индексацию вне хуков | Частота cursor_reset, длина очередей, нагрузка | Кандидат |
| RB-11 | Улучшение русской морфологии | Если лексический поиск будет слишком шумным или слабым, рассмотреть внешний морфологический слой как опциональный v2 | Метрики поиска, реальные жалобы, стоимость | Кандидат |

## Правила ведения

1. Этот файл не является нормативным для приёмки MiniMem-1 v1.6.
2. Любое решение из этого файла становится нормативным только после отдельной правки ТЗ.
3. Записии RB-01 и RB-02 обязательны к напоминанию при первом включении COMPACTION и при анализе таймаутов catch-up.
