# MiniMem-1 — Установка, бэкап и восстановление

Документ эксплуатации. Связан с «MiniMem-1 - Техническое задание v1.3»: раздел 26 (установка и
подключение к Hermes), раздел 4 (хранение), раздел 14 (дайджест), раздел 20 (конфигурация),
раздел 21 (CLI).

Факты о Hermes сверены с установленной системой: домашний каталог `%LOCALAPPDATA%\hermes`,
конфигурация `config.yaml` там же, Python — `hermes-agent\venv\Scripts\python.exe`.

---

## 1. Что нужно беречь

| Объект | Где | Происхождение | Критичность |
|---|---|---|---|
| Журнал | `<memory_root>/<project>/memory/*.md` | источник истины | **критично** — потеря невосстановима |
| Код MiniMem и его конфиг | каталог установки | рукописный | критично — без них журнал остаётся просто текстом |
| Записи хуков в `config.yaml` | `%LOCALAPPDATA%\hermes\config.yaml` | рукописные | желательно — восстанавливается за несколько минут по разделу 26 |
| Дайджесты | `<memory_root>/<project>/memory/digest/` | производные | не критично — `rebuild-digest` |
| `minimem.db` | `<memory_root>/minimem.db` | производная | не критично — `rebuild-index`; теряются счётчики и состояние сессий |
| Логи MiniMem | каталог логов | производные | не нужно |

Правило: **обязателен бэкап журнала**; всё остальное либо восстанавливается из журнала, либо
пишется заново по документу.

Одно важное следствие формата: журнал — обычный Markdown внутри хранилища. Если хранилище уже
попадает в ваш существующий бэкап, достаточно убедиться, что `<memory_root>` лежит внутри него.
Если нет — журнал копируется отдельно по разделу 3.

---

## 2. Развёртывание с нуля

Порядок для чистой машины или после переустановки Hermes.

1. **Проверить Python.** `hermes-agent\venv\Scripts\python.exe -V`. Хуки запускаются этим
   интерпретатором; сторонние пакеты не используются, нужна только стандартная библиотека.
2. **Разместить код.** Каталог MiniMem — отдельно от данных, например `C:\Projects\MEM_Hermes\minimem\`.
   Внутри: модули, три скрипта хуков (`hooks\pre_llm.py`, `hooks\post_llm.py`,
   `hooks\session_end.py`), конфигурационный файл `config.json`.
3. **Создать `memory_root`.** Каталог внутри хранилища; путь записать в `config.json`
   (`memory_root`). Журнал и дайджесты должны быть видны человеку и Obsidian.
4. **Зарегистрировать хуки** в `%LOCALAPPDATA%\hermes\config.yaml` по разделу 26.1 ТЗ:
   `pre_llm_call` (15 с), `post_llm_call` (30 с), `on_session_end` (30 с).
5. **Подтвердить команды.** При `hooks_auto_accept: false` Hermes спросит подтверждение в
   терминале при первом запуске. Подтвердить либо заранее задать `hooks_auto_accept: true`
   или `HERMES_ACCEPT_HOOKS=1`.
6. **Проверить установку:**

   ```shell
   hermes hooks list
   hermes hooks doctor
   ```

   Обе команды должны показать три наших хука без ошибок. Дополнительно —
   `hermes hooks test` с синтетической нагрузкой.
7. **Первый прогон.** Задать содержательную реплику в тестовом проекте. Проверить:
   - появился дневной файл журнала и одна запись в нём;
   - `minimem status` показывает запись;
   - `minimem verify` — без ошибок;
   - `minimem show <event_id>` возвращает оригинальную запись.
8. **Проверить возврат.** Начать новую сессию в том же проекте: на первом ходе должна вставиться
   выжимка предыдущей сессии. Если нет — смотреть лог и `digest_status`.

## 3. Резервное копирование

Принцип: копируется журнал (и, для быстроты восстановления, код с конфигом). Производные файлы
не копируются — они пересобираются.

**Куда.** Другой физический диск или внешний носитель. Только локально: внешние сервисы и облака
не используются (ограничение проекта — всё локально, без ключей и внешних систем).

**Как.** Обычное зеркальное копирование каталога журнала:

```shell
robocopy "<memory_root>" "D:\minimem-backup\<YYYY-MM-DD>\journal" /E /R:1 /W:1 /NFL /NDL
```

Журнал только дописывается, поэтому копия всегда целостна: файл прошлого дня не меняется,
сегодняшний копируется как есть. Остановка Hermes не требуется.

**Расписание.** Ежедневно (планировщик Windows, задание на `robocopy`), плюс копия после
завершения работы с проектом. Хранить: 30 последних ежедневных копий и одну копию от последнего
дня каждого месяца (12 штук). Объём небольшой — журнал это текст.

**Что копировать вместе с журналом:** каталог MiniMem с кодом и `config.json`, а также
`%LOCALAPPDATA%\hermes\config.yaml` — его может переписать обновление Hermes.

**Проверка бэкапа.** Раз в месяц — восстановление по разделу 4 в пустой каталог: если
`rebuild-index` проходит и число записей совпадает с рабочей системой, бэкап пригоден.

## 4. Восстановление после сбоя Windows

1. Вернуть работоспособность Hermes (установить заново, если пострадал).
2. Вернуть из бэкапа каталог MiniMem (код и `config.json`).
3. Вернуть из бэкапа журнал в `<memory_root>`. Если в бэкапе несколько дат — брать последнюю,
   но сверить, что дневной файл за текущий день не пустой: пустой файл означает, что копия
   делалась до записи, и тогда берётся предыдущая дата.
4. Удалить или переименовать `minimem.db`: производный слой пересобирается из журнала.
5. Пересобрать производные:

   ```shell
   minimem rebuild-index
   minimem rebuild-digest --all
   minimem verify
   ```

6. Сверить результат: `minimem status` — число записей в журнале и в индексе совпадает;
   `minimem verify` — без ошибок. Открыть последнюю запись журнала глазами: текст читается.
7. Зарегистрировать хуки заново (если `config.yaml` Hermes пострадал) и подтвердить их.
8. Первый ход после восстановления: выжимка прошлой сессии **не** вставится — состояние сессии
   потеряно вместе с `minimem.db`. Это ожидаемо, не ошибка.

---

## 5. Что теряется в разных случаях

| Сценарий | Последствия | Восстановление |
|---|---|---|
| Удалён `minimem.db` | Потеряны счётчики использования, состояние сессий, список снятых по правилу 2 | `rebuild-index`; снятые по правилам 1 и 3 пересчитываются, снятые по правилу 2 возвращаются в поиск |
| Удалены дайджесты | Возврат на первой сессии пустой | `rebuild-digest --all` |
| Потерян код MiniMem | Память цела: журнал лежит в хранилище и читается человеком | Развернуть код заново по разделу 2 |
| Сбой Windows | То же, что потеря `minimem.db`, при живом диске | Разделы 4 (шаги 4–7) |
| Потеря журнала без бэкапа | Память потеряна | Невосстановимо — это единственный веский аргумент за ежедневный бэкап |

---

## 6. Регламент

- **Ежедневно:** автоматическое копирование журнала (планировщик Windows).
- **После обновления Hermes:** `hermes hooks doctor` — обновление могло переписать `config.yaml`
  и снять регистрацию хуков.
- **Ежемесячно:** тренировка восстановления в пустой каталог по разделу 4.
- **При изменении конфигурации MiniMem:** обновить копию `config.json` в бэкапе.
